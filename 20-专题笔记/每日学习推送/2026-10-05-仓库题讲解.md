## 题目

定义抽象基类 Motor，保存品牌 brand，提供 start()、stop()、setSpeed(int rpm) 与 displayInfo()。派生出 DaMiaoMotor 与 DJIMotor，分别实现自己的启动与停止行为。让给定测试程序通过 Motor* 统一调用两种电机，并在 delete 时正确析构。

原测试程序依次调用每台电机的 start()、setSpeed(1500)、displayInfo()、stop()，最后通过基类指针释放对象。本次不修改作业源码，不提交作业。

## 核心接口

下面是原文件已有完整实现的关键行，不是替换原文件的完整程序：

~~~cpp
virtual void start() = 0;
virtual void stop() = 0;
virtual ~Motor() {
    cout << "Motor " << brand << " destroyed." << endl;
}
~~~

基类定义共同接口，派生类实现各自行为。调用方只需知道“这是一个 Motor”，运行时仍能根据实际对象决定启动或停止哪种电机，这叫运行时多态。

纯虚函数声明末尾的 = 0 要求可实例化的派生类提供实现，Motor 因而成为抽象类，不能直接创建 Motor 对象。但可以定义 Motor*，让它指向具体电机：

~~~cpp
Motor* motors[2];
motors[0] = new DaMiaoMotor();
motors[1] = new DJIMotor();
~~~

两个指针的声明类型都是 Motor*，实际对象不同。调用 motors[0]->start() 时执行达妙版本，调用 motors[1]->start() 时执行大疆版本。virtual 让程序根据实际对象选择函数。

派生类函数后面的 override 让编译器检查是否确实重写了基类虚函数。例如误写 void start(int x) override，参数与基类不一致，编译器会报错，帮助发现签名错误。

原代码的 setSpeed 没有声明为虚函数，通过 Motor* 调用时执行基类实现。它读取每个对象自己的 brand，所以仍会输出不同品牌。输出内容不同，并不必然说明发生虚函数多态。

此外，原程序的 setSpeed(1500) 只打印文字，没有实现真实电机驱动或闭环调速。此题验证 C++ 接口组织；实物调速以后还需驱动协议、PWM 或其他硬件逻辑。

## 为什么析构函数也要 virtual

最后执行 delete motors[i] 时，指针是 Motor*，实际对象是派生类。基类有虚析构函数，才能正确析构整个对象：先执行派生类析构，再执行基类析构。

对本题的对象，若基类析构非虚，通过基类指针 delete 派生类对象会导致未定义行为，不能只理解成“少打印一句话”。
