# 笔记库云端备份说明

本库（`D:\学习笔记\大学`）已经接入 GitHub 私有仓库做**带历史的异地备份**。

- 远端：`https://github.com/AngryInvolutionKing/obsidian-university`（private）
- 分支：`main`
- 插件：**obsidian-git**，每 **15 分钟**自动 commit 一次，并 push 到远端

## 三层存储各管什么

| 层 | 范围 | 特点 |
|---|---|---|
| **Syncthing** | PC ↔ 手机，实时双向 | 日常同步靠它 |
| **Git + GitHub** | 带历史的异地备份 | 电脑炸了/误删了能找回历史版本 |
| **本地磁盘** | —— | —— |

两层**互不干扰**：`.stignore` 里加了 `(?d).git`，Syncthing **不同步 `.git` 目录**。
原因：两台设备同时写 `.git` 会损坏仓库；跨设备那一层由 GitHub 负责。

> 所以手机上 Obsidian 的 Git 插件永远显示 "Git is not ready"，**这是正常的，不影响使用**。

## 哪些东西不进仓库，为什么

`.gitignore` 的原则是：**只排除「机器本地状态 / 可重装缓存 / 超限大文件」，笔记和插件配置一律入库。**

| 排除项 | 理由 |
|---|---|
| `40-Attachments/engbook/media/` | 里面有个 **117 MB 的视频**，超过 GitHub **单文件 100 MB 硬上限**，push 会被直接拒绝 |
| `.opencode/` `.copilot/` `copilot/` `.claude/` `.agents/` `tmp/` | AI 会话缓存，可重建 |
| `.obsidian/workspace*.json`、`.obsidian/cache/` | 每台设备各自的窗口布局，同步会打架 |
| `.obsidian/plugins/*/node_modules/` | 可重装 |
| `.stfolder/` `.stversions/` `~syncthing~*.` | Syncthing 自己的状态 |
| `.trash/`、`Thumbs.db`、`desktop.ini`、`*.tmp` | 系统垃圾 |

入库规模：**753 文件 / 147.2 MB**，最大单文件 9.25 MB（`7.UART.pdf`）。

> 密钥安全已核查：`.obsidian/plugins/*/data.json` 里**没有任何明文 apiKey/token**（Obsidian Copilot 把密钥存在系统钥匙串里），所以 `.obsidian` 可以放心入库。

## 首次推送踩的坑（已解决，写下来免得以后再查）

第一次推送两种方式都失败：

```
error: RPC failed; curl 55 Send failure: Connection was reset
send-pack: unexpected disconnect while reading sideband packet
fatal: the remote end hung up unexpectedly
```

但网络本身是通的（代理正常、`github.com` 直接可达），是 **147 MB 大包单次上传被中途掐断**。

**真正解决问题的是仓库本地的 git 配置**（写进 `.git/config`，不在全局）：

```
http.version   = HTTP/1.1                # 避开 HTTP/2 在多路复用下被 reset
http.postBuffer= 524288000               # 500 MB，够装下整个包
http.lowSpeedLimit = 1000                # 低于 1 KB/s ...
http.lowSpeedTime  = 60                  # ... 持续 60 秒才判定断线（默认 1 秒太急）
http.proxy     = http://127.0.0.1:7890   # 关键：Obsidian 里 spawn 的 git 拿不到系统代理环境变量
core.autocrlf  = false                   # 库要被 Syncthing 同步到 Linux 手机，字节级原样存
core.quotepath = false                   # 中文路径不转义，日志可读
```

`http.proxy` 写在**仓库配置**里而不是设环境变量，是有意为之：obsidian-git 从 Obsidian 进程里启动 git 时**继承不到** `HTTPS_PROXY`，只有仓库配置才一定生效。

另外把首次导入拆成了 **4 个提交**（每批约 40 MB）。事后看，第一批实际上仍把整个 119.66 MiB 的包一次发完了（耗时 505 秒），后面三批只花 2–3 秒——**所以起决定作用的是上面那份配置，不是拆分**；拆分的价值在于重试粒度更细。

以后 obsidian-git 每次只提交改动，都是小包，不会再遇到这个问题。
