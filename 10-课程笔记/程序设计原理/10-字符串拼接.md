# 10 字符串拼接（mystrcat · 读写双指针）

**考点**：C 风格字符串的 `'\0'` 结尾、三段式拼接流水线（走尾 → 搬运 → 补哨）、`char*` 与 `const char*` 的角色分工、读写双指针为什么必须各自 `++`、数组退化传参、`char message[50] = {0}` 零初始化的必要性

> 语言机制（首地址、`'\0'`、步长、const 三种组合）已抽到 [[知识点专题]] 的 K01 / K02，本篇专注题目本身和双指针搬运过程。

## 题目

自己实现 `mystrcat`（不许用 `<cstring>` 的 `strcat`），把六段字面量依次拼进同一个数组，最后一次性输出：

```
I'm the storm that is approaching!
```

## 代码

```cpp
#include <iostream>
using namespace std;

void mystrcat(char* ptr, const char* add_char);

int main()
{
    char message[50] = {0};
    mystrcat(message, "I'm ");
    mystrcat(message, "the ");
    mystrcat(message, "storm ");
    mystrcat(message, "that ");
    mystrcat(message, "is ");
    mystrcat(message, "approaching!");
    cout << message << endl;
}

void mystrcat(char* ptr, const char* add_char)
{
    while (*ptr != '\0')        // ① 先走到目标串末尾（踩在 '\0' 上停）
    {
        ptr++;
    }
    while (*add_char != '\0')   // ② 读一个、写一个，两个指针同步各挪一格
    {
        *ptr = *add_char;
        ptr++;
        add_char++;
    }
    *ptr = '\0';                // ③ 给拼完的结果补上新的结束符
}
```

三步是一条流水线：**①找到尾 → ②从尾往后搬 → ③封口**。原代码只写了 ①，②③ 才是真正干活的——只写 ① 能编译，但程序输出空行（见「坑」）。

## 双指针分工：add_char 管读，ptr 管写

### 两块不同的内存，各指各的

以 `mystrcat(message, "the ")` 为例，此时 message 已是 `"I'm "`，① 结束后：

```text
源串（只读，const char*）
add_char →  't'   'h'   'e'   ' '   '\0'
             ↑ 从这读

目标（message，可写，char*）
             'I'  '\''  'm'   ' '   '\0'  ·  ·  ·  ...   （· = 仍是 {0} 留下的 '\0'）
                                      ↑ ptr 从这写
```

两个指针互不相干，只是**每轮同时往前走一格**：读的位置和写的位置都得各自前进，不然就出问题。

### 逐轮追踪：读一个、写一个、各挪一格

message 当前是 `"I'm "`，继续拼 `"the "`：

| 轮次 | 读 `*add_char` | 写到 `*ptr` 后 message 变成 | 然后 `ptr++` | 然后 `add_char++` |
| --- | --- | --- | --- | --- |
| 1 | 't' | "I'm t" | 指向下一格 | 指向 'h' |
| 2 | 'h' | "I'm th" | 再往后 | 指向 'e' |
| 3 | 'e' | "I'm the" | 再往后 | 指向 ' ' |
| 4 | ' ' | "I'm the " | 再往后 | 指向 '\0' |
| 5 | '\0' → 条件不成立，出循环，`*ptr = '\0'` 封口 | "I'm the " | — | — |

每轮写的恰好是上一轮 `'\0'` 踩过的格子——旧结束符被新字符覆盖，串就这样往后长。

### 如果只加一个 `++`（两个坏版本，都实测过）

**只 `add_char++`，不 `ptr++`：**

```cpp
while (*add_char != '\0')
{
    *ptr = *add_char;
    add_char++;          // 只动读指针
}
```

ptr 一直指着同一格，每读一个字符都盖写在同一格上，前面的全被后面的覆盖；循环结束后 `*ptr = '\0'` 连最后一个字符也抹掉。实测：整个程序输出**空串**——六次调用全白做，message 从头到尾没长过一个字符。

**只 `ptr++`，不 `add_char++`：**

```cpp
while (*add_char != '\0')
{
    *ptr = *add_char;
    ptr++;               // 只动写指针
}
```

`*add_char` 永远是源串第一个字符，永远不是 `'\0'`，条件恒真 → **死循环**；同时 ptr 一路往后写同一个字符，越过 `message[49]` 就是把后面的内存写坏（UB）。不敢真跑死循环版，加了 `count < 49` 保险丝限次实测：输出 49 个 `t`——「一直重复写源串第一个字符」这个趋势被完整复现，去掉保险丝就是越界。

### 打个比方：抄书

- `add_char` 是**眼睛看的位置**（读到哪了）；
- `ptr` 是**笔下写的位置**（写到哪了）。

抄一个字，眼睛往右移一个字，笔也往右移一个字。只动眼睛：笔老写同一处，纸上只剩反复涂改的最后一笔；只动笔：眼睛死盯着第一个字，你会一直重复抄同一个字，纸写满了还停不下来笔（越界）。

一句话记住：**add_char 管「读」、ptr 管「写」，两个独立的指针，每搬一个字符各自前进一格——所以两个都要 `++`。**

## 要点

- 参数类型即分工说明书：`ptr` 要写 → `char*`；`add_char` 只读 → `const char*`（见 [[知识点专题]] K01）。`add_char++` 合法，因为 const 锁的是内容、不是指针本身。
- 传的从来不是整串字符，是**首地址**：`mystrcat(message, "the ")` 传进去的是 message 退化出的 `char*` 和字面量的 `const char*`，函数靠地址「顺藤摸瓜」（见 K02）。
- `char message[50] = {0}` 把整个数组清零。如果写成 `char message[50];`，里面是垃圾值，步骤 ① 找 `'\0'` 可能一路冲出数组——UB。**靠 `'\0'` 定位末尾的前提是它真的存在。**
- 容量账：最终串 34 个字符 + 1 个 `'\0'` = 35 格 ≤ 50，装得下。这个版本的 `mystrcat` 不知道 message 有多长，**不检查越界**，全靠调用者保证——和标准库 `strcat` 一个脾气（`strncat` / `strcat_s` 才是带长度的版本）。
- `cout << message` 一次输出整串：`char*` 交给 `cout` 时按 C 风格字符串处理，从首地址打到 `'\0'` 为止——和打印 int 完全两套逻辑。

## 坑

- **只写步骤 ① 的版本能编译通过**，`-Wextra` 只给一条 `warning: unused parameter 'add_char'`，运行输出空行。「能跑」和「跑了但不干活」是两回事，编译器的 unused parameter 警告就是为这种半成品准备的。
- 两个指针少 `++` 任何一个，症状完全不同：少 `ptr++` 是**静默覆盖**（输出空串，不崩不报）；少 `add_char++` 是**死循环 + 越界写**（可能崩可能不崩，都是 UB）。前者好查（结果不对），后者危险（结果不对之前内存已经坏了）。
- `ptr++` 与 `add_char++` 步长都是 1 字节，因为都指向 `char`；同一套写法换成 `int*` 每步就是 4 字节（K02 第 5 点）。
- 步骤 ③ `*ptr = '\0'` 不能省：省了的话 message 结尾没有哨兵，下次调用步骤 ① 会沿 `{0}` 留下的零继续找（碰巧还能停，因为初始化过），但换一块没清零的内存就直接冲出去——别把「碰巧对」当「对」。

## 测试记录

环境：g++ (MinGW-W64 ucrt-posix-seh) 16.1.0，`-std=c++17 -Wall -Wextra -O2`。

| 版本 | 改动 | 实测结果 |
| --- | --- | --- |
| 完整版 | — | `I'm the storm that is approaching!`，`strlen` = 34，无警告 |
| 缺 `ptr++` | 搬运循环只剩 `add_char++` | 输出空串：所有字符盖写同一格，尾部 `'\0'` 把最后一格也抹掉 |
| 缺 `add_char++` | 搬运循环只剩 `ptr++` | 死循环；加 `count < 49` 保险丝限次后输出 49 个 `t`，复现「重复写源串首字符直至越界」 |
| 只有步骤 ① | 半成品（原代码状态） | 编译通过（unused parameter 警告），输出空行 |
