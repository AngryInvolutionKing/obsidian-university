## 完整题干与真实源文件

题目要求：电机供电为 12V；电机端子 M1/M2 接 L298N 输出；L298N 必须和单片机共地；编码器 C1/C2 接定时器编码器模式的两根引脚；编码器 VCC 接 5V、GND 接 GND。源码要求按 L298N 的“单 PWM 加双 IO”逻辑实现 `motorRun`，设置 PWM 比较值，并让电机以固定占空比转动，同时用编码器计数确认“转了多少”。交付本文件和电机转动的视频或现象。

本题的最小目标是验证“控制命令到驱动输出”和“机械运动到编码器计数”这两条链路均有可观察反应。它不重复上一专题的角速度换算，也不把计数变化冒充为精确转角或速度标定。

## 可替换的 HAL 代码骨架

下列 `Board_` 函数必须按实际 L298N 模块、CubeMX 引脚和 PWM 定时器实现；这些名称不是 HAL 自带 API。`forward` 只表示逻辑方向，实际正反转要由电机安装方向和 IN1/IN2 接线验证。

~~~cpp
#include "main.h"
#include <cstdint>

extern TIM_HandleTypeDef htimMotorPwm;   // 替换为实际 PWM 定时器句柄
extern TIM_HandleTypeDef htimEncoder;    // 替换为实际编码器定时器句柄

static constexpr uint32_t kObserveMs = 500U;

struct MotorCheck {
    bool running = false;
    bool encoder_changed = false;
    uint16_t encoder_before = 0;
    uint32_t started_ms = 0;
};

static MotorCheck check{};

// 以下函数必须根据实际板卡补全。
bool Board_SetL298NDirection(bool forward);
bool Board_SetPwmPercent(uint8_t duty_percent);
void Board_StopMotor();

bool App_MotorCheckBegin(uint8_t duty_percent, bool forward) {
    if (duty_percent == 0U || duty_percent > 100U) {
        return false;
    }

    if (HAL_TIM_PWM_Start(&htimMotorPwm, MOTOR_PWM_CHANNEL) != HAL_OK) {
        return false;
    }
    if (HAL_TIM_Encoder_Start(&htimEncoder, TIM_CHANNEL_ALL) != HAL_OK) {
        return false;
    }
    if (!Board_SetL298NDirection(forward) || !Board_SetPwmPercent(duty_percent)) {
        Board_StopMotor();
        return false;
    }

    check.encoder_before = __HAL_TIM_GET_COUNTER(&htimEncoder);
    check.started_ms = HAL_GetTick();
    check.encoder_changed = false;
    check.running = true;
    return true;
}

void App_MotorCheckService() {
    if (!check.running) {
        return;
    }

    const uint32_t now = HAL_GetTick();
    if (now - check.started_ms < kObserveMs) {
        return;
    }

    const uint16_t encoder_after = __HAL_TIM_GET_COUNTER(&htimEncoder);
    check.encoder_changed = encoder_after != check.encoder_before;
    Board_StopMotor();
    check.running = false;
}
~~~

`MOTOR_PWM_CHANNEL`、`htimMotorPwm`、`htimEncoder`、IN1/IN2 引脚和 PWM 极性均是待替换配置。初始化后调用 `App_MotorCheckBegin(30, true)`，主循环持续调用 `App_MotorCheckService()`。500ms 是本题笔记选择的观察窗口，不是讲义规定的唯一值。`encoder_changed` 只能说明计数器值发生变化，不能由此推出旋转方向、转速、减速比或实际转角。

## 语法、API 与寄存器概念

`uint8_t` 将占空比限制为小范围无符号整数；入口先拒绝零占空比和超过 100 的数，避免把无运动命令误判为接线故障。`static MotorCheck` 保留开始计数、开始时刻和结果，供主循环多次调用时继续使用。`now-started` 采用无符号减法，可在正常的毫秒计时回绕场景中判断经过时间。

`HAL_TIM_PWM_Start` 启动指定 PWM 通道。`Board_SetPwmPercent` 内部应结合实际自动重装值 ARR，使用 `__HAL_TIM_SET_COMPARE` 写 CCR；PWM 频率、通道和极性都需由 CubeMX/原理图确认。`HAL_GPIO_WritePin` 可用于设置 L298N 的方向 IO，但单 PWM 加双 IO 的 IN1/IN2 高低电平组合、ENA 接法和模块使能逻辑不能凭题目文字猜测。

`HAL_TIM_Encoder_Start(&htimEncoder,TIM_CHANNEL_ALL)` 启动编码器模式通道，`__HAL_TIM_GET_COUNTER` 读取 CNT。C1/C2 连接的是编码器模式输入，不是 PWM 输出。计数开始值与观察窗口后的值不同，只能证明计数路径有变化；需要已知每圈计数、采样间隔和回绕处理，才能进一步计算角速度，见 [[编码器回绕与电机角速度]]。

## 控制流程

先在断电状态核对电机到 L298N 输出端、12V 电源、共地、编码器 C1/C2、编码器 5V/GND 和模块极性。软件启动 PWM 与编码器计数，再设置逻辑方向和低占空比。记录 CNT 起始值后等待固定观察窗口，读取第二次 CNT；若数值变化，则停止 PWM 并报告“编码器计数已变化”。若未变化，先停止输出，再按接线、供电、共地、PWM、方向 IO、编码器供电和输入配置逐项排查。

## 常见错误

常见错误包括 L298N 与 MCU 没有共地、将电机 12V 与编码器 5V 混接、降压模块正负极接反、编码器 C1/C2 接到普通 GPIO 而未配置编码器模式、PWM 通道和实际 ENA/ENB 接线不一致、只改 CCR 却没启动 PWM、将计数不变误判为软件必然错误、以及电机机械受阻却继续提高占空比。计数变化也不能证明方向正确或速度符合预期；方向和速度需要单独验证。

## 最小自检

主机端独立测试文件位于 `C:\Users\zhang\.codex\artifacts\motor-encoder-check-20261017\motor_check_test.cpp`，已用本机 g++ 的 C++17、`-Wall -Wextra -Werror` 编译运行。测试覆盖占空比 0、30、100 与越界拒绝、毫秒计时回绕以及编码器计数变化判断。输出为 `motor command and encoder check logic passed`。

硬件最小自检应先在断电状态按题面核对 12V、5V、GND 与共地；确认 PWM 频率和方向 IO 后，采用低占空比、短观察窗口启动。观察电机输出轴是否运动、CNT 是否变化，并立即停止。无视频/现象、计数记录和接线核对表时，不应把作业标为已完成。
