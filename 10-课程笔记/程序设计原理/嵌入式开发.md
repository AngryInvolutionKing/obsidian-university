# 嵌入式开发：传感器与电机练习

## 练习一：传感器数据读取（枚举 · 结构体 · 宏）

### 一、题目（完整代码）

传感器数据读取程序：定义状态枚举、传感器结构体、异常判断宏，遍历打印每个传感器信息，并在检测到异常时给出提示。以下为完整可运行代码（`main` 保持原题固定写法）。

```cpp
#include <iostream>
using namespace std;

enum Status { OK, WARNING, ERROR };

// 结构体：传感器数据
struct SensorData {
    int id;
    int value;
    Status status;
};

// 宏：非 OK 即为异常
#define IS_ABNORMAL(status) ((status) != OK)

// 状态转字符串
const char* getStatusString(Status s) {
    switch (s) {
        case OK:      return "OK";
        case WARNING: return "WARNING";
        case ERROR:   return "ERROR";
        default:      return "UNKNOWN";
    }
}

// 打印传感器信息（指针传参）
void printSensor(SensorData* p) {
    cout << "Sensor #" << p->id
         << " | value=" << p->value
         << " | status=" << getStatusString(p->status) << endl;
}

// main 函数固定不变
int main() {
    SensorData sensors[3] = {
        {1, 85,  OK},
        {2, 120, WARNING},
        {3, 200, ERROR}
    };

    for (int i = 0; i < 3; i++) {
        printSensor(&sensors[i]);
        if (IS_ABNORMAL(sensors[i].status)) {
            cout << "  >>> ABNORMAL DETECTED!" << endl;
        }
    }
    return 0;
}
```

### 二、语法点拆解

#### 1. 枚举 enum

```cpp
enum Status { OK, WARNING, ERROR };
```

- 枚举把一组相关的整型常量集中命名，提高可读性。
- 不指定值时，**枚举量从 0 开始依次递增**：`OK=0`、`WARNING=1`、`ERROR=2`。
- 枚举本质是整型，可以直接参与比较、判断，例如 `status != OK`。
- 本题中「异常」= 不是 `OK` 的状态，即 `WARNING` 和 `ERROR`。

#### 2. 结构体 struct

```cpp
struct SensorData {
    int id;
    int value;
    Status status;   // 成员类型可以是已定义的枚举
};                   // ← 注意结尾的分号不能漏
```

- `struct` 用来把多个不同类型的数据打包成一个整体。
- 结构体成员可以是基本类型（`int`），也可以是自定义类型（`Status`）。
- 访问成员：
  - 用**变量**访问：`.`（点号），如 `sensors[i].status`
  - 用**指针**访问：`->`（箭头），如 `p->status`

#### 3. 结构体数组与初始化

```cpp
SensorData sensors[3] = {
    {1, 85,  OK},        // 按成员声明顺序赋值
    {2, 120, WARNING},
    {3, 200, ERROR}
};
```

- `sensors[3]` 是含 3 个 `SensorData` 的数组。
- 用 `{}` 列表初始化每个元素，**顺序必须和结构体成员声明顺序一致**：`id, value, status`。
- 访问：`sensors[i]` 是第 i 个元素，`sensors[i].value` 是该元素的 value 成员。

#### 4. 宏定义 #define

```cpp
#define IS_ABNORMAL(status) ((status) != OK)
```

- `#define` 是预处理指令，在编译前做**纯文本替换**，结尾**不加分号**。
- 带参数的宏：`#define 宏名(参数) 替换文本`。
- **每个参数和整个表达式都要用括号包裹**，防止运算符优先级出错。
  - 例：若写成 `#define IS_ABNORMAL(status) status != OK`，当传入 `a + b` 之类表达式时会展开错误。
- 使用时像函数一样调用：`IS_ABNORMAL(sensors[i].status)`，会被替换成 `((sensors[i].status) != OK)`，结果是 `true/false`。

#### 5. 函数：返回字符串

```cpp
// 返回 const char*（C 风格字符串）
const char* getStatusString(Status s) {
    switch (s) {
        case OK:      return "OK";
        case WARNING: return "WARNING";
        case ERROR:   return "ERROR";
        default:      return "UNKNOWN";
    }
}
```

- `switch-case` 适合对枚举/整型做多分支判断，**每个 case 都要 `return` 或 `break`**。
- 返回类型 `const char*` 表示字符串字面量的指针（也可用 `string`，需 `#include <string>`）。
- `default` 分支处理意外情况，是良好习惯。

#### 6. 函数：指针传参

```cpp
// main 中调用 printSensor(&sensors[i])，& 取地址 → 传入指针
void printSensor(SensorData* p) {
    cout << "Sensor #" << p->id
         << " | value=" << p->value
         << " | status=" << getStatusString(p->status) << endl;
}
```

- `&sensors[i]` 取第 i 个元素的**地址**，所以形参必须是**指针** `SensorData*`。
- 指针访问成员用 `->`：`p->id` 等价于 `(*p).id`。
- 传指针（或引用）避免整体拷贝，效率高，也更贴近嵌入式/底层开发习惯。

### 三、预期输出

```
Sensor #1 | value=85 | status=OK
Sensor #2 | value=120 | status=WARNING
  >>> ABNORMAL DETECTED!
Sensor #3 | value=200 | status=ERROR
  >>> ABNORMAL DETECTED!
```

### 四、要点 & 易错点小结

| 知识点 | 关键语法 | 常见坑 |
| --- | --- | --- |
| 枚举 | `enum Status{OK,...};` | 忘记默认从 0 开始编号 |
| 结构体 | `struct{...};` | **结尾漏写分号** |
| 成员访问 | 变量用 `.`，指针用 `->` | 指针误用 `.` |
| 数组初始化 | `{{1,85,OK},...}` | 顺序和成员声明不一致 |
| 宏 | `#define 名(参) 文本` | 参数/表达式**不加括号**、结尾**误加分号** |
| 指针传参 | 形参 `T*`，调用传 `&x` | 调用传地址但形参不是指针 |
| switch | `case ...: return/break;` | 漏 `break` 造成穿透 |

> [!tip] 核心串联
> `main` 用 `&sensors[i]` 传**地址** → `printSensor` 用**指针** `SensorData*` 接收 → 用 `->` 取成员 → 把 `status` 交给 `getStatusString` 转成可读文本；同时 `IS_ABNORMAL` 宏在编译前被替换成「是否不等于 OK」的判断。

## 练习二：电机多态控制（继承 · 虚函数 · 抽象类）

### 一、题目（完整代码）

多态电机控制程序：用抽象基类 `Motor` 统一电机接口，`DaMiaoMotor`（达妙）与 `DJIMotor`（大疆）按各自方式实现启动/停止；`main` 通过基类指针数组统一操作不同品牌的电机，最后按正确顺序析构。以下为完整可运行代码（`main` 保持原题固定写法）。

```cpp
#include <iostream>
#include <string>
using namespace std;

// Motor 抽象基类
class Motor {
public:
    Motor(const string& b) : brand(b) {
    }

    // 虚析构：delete 基类指针时先调用派生类析构，再调用这里
    virtual ~Motor() {
        cout << "Motor " << brand << " destroyed." << endl;
    }

    // 各品牌启动方式不同 -> 纯虚函数，派生类必须实现，Motor 因此不能实例化
    virtual void start() = 0;

    // 各品牌停止方式不同 -> 纯虚函数
    virtual void stop() = 0;

    // 各品牌完全一样 -> 普通成员函数即可
    void setSpeed(int rpm) {
        cout << brand << " motor speed set to " << rpm << " RPM." << endl;
    }

    // 各品牌格式一样，只是品牌名不同 -> 虚函数给默认实现
    virtual void displayInfo() {
        cout << "Brand: " << brand << endl;
    }

protected:
    string brand;
};

// DaMiaoMotor 派生类
class DaMiaoMotor : public Motor {
public:
    DaMiaoMotor() : Motor("DaMiao") {
    }

    ~DaMiaoMotor() override {
        cout << "DaMiao motor destroyed." << endl;
    }

    void start() override {
        cout << "DaMiao motor started with high frequency." << endl;
    }

    void stop() override {
        cout << "DaMiao motor stopped with brake." << endl;
    }
};

// DJIMotor 派生类
class DJIMotor : public Motor {
public:
    DJIMotor() : Motor("DJI") {
    }

    ~DJIMotor() override {
        cout << "DJI motor destroyed." << endl;
    }

    void start() override {
        cout << "DJI motor started quietly." << endl;
    }

    void stop() override {
        cout << "DJI motor stopped slowly." << endl;
    }
};

// 以下 main 函数固定不变，禁止修改
int main() {
    Motor* motors[2];
    motors[0] = new DaMiaoMotor();  // 达妙电机
    motors[1] = new DJIMotor();     // 大疆电机
    for (int i = 0; i < 2; i++) {
        cout << "--- Testing Motor " << i + 1 << " ---" << endl;
        motors[i]->start();
        motors[i]->setSpeed(1500);
        motors[i]->displayInfo();
        motors[i]->stop();
        cout << endl;
    }
    for (int i = 0; i < 2; i++) {
        delete motors[i];
    }
    return 0;
}
```

### 二、语法点拆解

#### 1. 继承：`class 派生类 : public 基类`

```cpp
class DaMiaoMotor : public Motor { ... };
```

- `: public Motor` 表示**公有继承**：`Motor` 的 `public` 成员在派生类中仍是 `public`，`protected` 成员仍是 `protected`。
- 派生类自动获得基类的成员（`brand`、`setSpeed`、`displayInfo` 等），**不需要也不应该重新声明**——这就是复用：两个派生类都没有写 `brand`，用的都是基类那一份。
- 嵌入式语境：`Motor` 是所有电机的「统一驱动接口」，达妙/大疆是具体型号。以后新增品牌电机，`main` 一行都不用改（面向接口编程）。

#### 2. 基类构造函数与初始化列表

```cpp
Motor(const string& b) : brand(b) {}        // 基类：带参构造
DaMiaoMotor() : Motor("DaMiao") {}          // 派生类：初始化列表调用基类构造
```

- 基类构造函数**带参数**，派生类构造时**必须**在初始化列表里显式调用它，把 `"DaMiao"` 传进去；漏写会直接编译错误（基类没有默认构造可调）。
- 构造顺序：**先基类后派生类**——先执行 `Motor("DaMiao")` 把 `brand` 初始化好，再执行 `DaMiaoMotor` 的构造体。
- 形参 `const string&` 用 const 引用：避免字符串拷贝，同时保证不被修改。

#### 3. 访问控制：public / protected / private

```cpp
protected:
    string brand;
```

| 访问级别 | 本类 | 派生类 | 类外（main） |
| --- | --- | --- | --- |
| `public` | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ❌ |
| `private` | ✅ | ❌ | ❌ |

- `brand` 设为 `protected`：派生类（如 `displayInfo` 的将来重写版）可以直接用，但 `main` 里不允许 `motors[0]->brand` 这样访问。
- 经验法则：**希望子类能用、但不想暴露给外部**的数据 → `protected`。

#### 4. 纯虚函数与抽象类

```cpp
virtual void start() = 0;   // = 0 表示纯虚函数
virtual void stop()  = 0;
```

- 带纯虚函数的类是**抽象类**：`Motor m;` 会编译错误，**不能实例化**，只能当基类/指针类型用。
- `= 0` 的含义：基类只规定「必须有这个功能」，**不提供任何实现**，派生类必须重写，否则派生类也还是抽象类（`DaMiaoMotor d;` 同样会报错——直到 start/stop 都实现为止）。
- 设计动机：各品牌启动/停止方式**完全不同**（高频启动 vs 安静启动），放在基类里没法写出通用实现，只能强制派生类自己写。

#### 5. 三种成员函数的选择依据（本题核心设计）

| 情况 | 选择 | 本题例子 |
| --- | --- | --- |
| 各品牌行为**完全相同** | 普通成员函数（不加 virtual） | `setSpeed` |
| 各品牌**格式一样、只差数据** | 虚函数 + 基类默认实现，派生类**可以不重写** | `displayInfo`（brand 不同但打印格式相同） |
| 各品牌实现**完全不同** | 纯虚函数 `= 0`，派生类**必须重写** | `start`、`stop` |

- 注意 `displayInfo`：两个派生类都**没有重写**它，运行时执行的是基类版本——因为 `brand` 已经是各自构造时传入的 `"DaMiao"`/`"DJI"`，基类一份实现就能输出不同品牌名，这正是「代码复用 + 数据差异化」。
- `setSpeed` 不加 virtual：所有品牌行为一模一样，加 virtual 只会白白增加虚表开销（嵌入式里对性能/内存敏感时是有意义的取舍）。

#### 6. `override` 关键字

```cpp
void start() override { ... }
~DaMiaoMotor() override { ... }
```

- C++11 引入，写在派生类函数声明末尾，表示「我确认这是在重写基类虚函数」。
- 作用是**编译期防错**：如果函数签名写错（比如把参数写成 `int rpm` 与基类不一致、把 `stop` 拼成 `stope`），没有 `override` 时编译器会当成你定义了一个「新函数」而**静默通过**，运行时才发现调不到；加了 `override` 则直接报错。
- 构造函数不写 `override`（构造不能被重写），析构函数可以写。

#### 7. 运行时多态：基类指针 + new

```cpp
Motor* motors[2];
motors[0] = new DaMiaoMotor();   // 基类指针指向派生类对象 ✅
// DaMiaoMotor* p = new Motor(); // 反过来 ❌ 编译错误
```

- **多态 = 同一句 `motors[i]->start()`，对不同对象执行不同代码**：i=0 时跑达妙版，i=1 时跑大疆版。`main` 里的循环完全不知道具体品牌，这就是「一个接口，多种形态」。
- 实现机制：带虚函数的类有一张**虚函数表（vtable）**，对象里存一个 vptr 指向它。通过基类指针调用 `virtual` 函数时，运行时经 vptr 查表，找到**对象真实类型**的函数版本——这叫**动态绑定/晚绑定**。
- 对比：`setSpeed` 不是虚函数，走**静态绑定**，编译期就确定调用基类版本（本题里恰好行为一致，无所谓）。
- 方向记忆：**允许「向上」**（派生类对象赋给基类指针，因为派生类"是一种"基类），**禁止「向下」**（基类对象赋给派生类指针，基类缺少派生类成员）。

#### 8. 虚析构函数与析构顺序

```cpp
virtual ~Motor() { ... }     // 基类析构必须加 virtual
~DaMiaoMotor() override { ... }
```

- `delete motors[i]` 时，`motors[i]` 的**静态类型是 `Motor*`**。如果基类析构**不是** virtual，只会调用 `~Motor()`，派生类部分不会被析构——派生类里若有堆资源（缓冲区、句柄）就**泄漏**，且属未定义行为。
- 加了 virtual 后走动态绑定：调用到对象**真实类型**的析构函数，析构顺序为**先派生类、后基类**（与构造正好相反）：

```
DaMiao motor destroyed.     ← 先 ~DaMiaoMotor()
Motor DaMiao destroyed.     ← 再 ~Motor()
```

- 经验法则：**只要一个类打算被继承、并且可能通过基类指针 delete，析构函数就必须写成 virtual**——这是面试和实战双重高频考点。

#### 9. 动态内存管理：new / delete

- `new DaMiaoMotor()` 在**堆**上创建对象并返回指针；用完后必须 `delete`，否则内存泄漏。
- 本题两个 for 循环职责分明：第一个循环**使用**对象，第二个循环**释放**对象——嵌入式设备内存有限，「谁 new 谁 delete」是纪律。
- 数组版本对应 `new T[n]` / `delete[]`；本题是「指针数组、每个元素 new 一个对象」，所以逐个 `delete`，不用 `delete[]`。

### 三、预期输出（已编译运行验证）

```
--- Testing Motor 1 ---
DaMiao motor started with high frequency.
DaMiao motor speed set to 1500 RPM.
Brand: DaMiao
DaMiao motor stopped with brake.

--- Testing Motor 2 ---
DJI motor started quietly.
DJI motor speed set to 1500 RPM.
Brand: DJI
DJI motor stopped slowly.

DaMiao motor destroyed.
Motor DaMiao destroyed.
DJI motor destroyed.
Motor DJI destroyed.
```

- 注意最后四行：delete 按 `motors[0]`、`motors[1]` 的顺序执行，每个对象都是**先派生类析构、后基类析构**。
- `displayInfo` 输出的品牌名不同，但执行的都是**基类的同一份代码**（派生类未重写）。

### 四、要点 & 易错点小结

| 知识点 | 关键语法 | 常见坑 |
| --- | --- | --- |
| 继承 | `class D : public B` | 漏写 `: public`；派生类里重复声明基类已有的 `brand` |
| 基类构造调用 | `DaMiaoMotor() : Motor("DaMiao")` | 基类构造带参却漏写初始化列表 → 编译错误 |
| 纯虚函数 | `virtual void f() = 0;` | 试图实例化抽象类 `Motor m;`；派生类漏实现 → 派生类也是抽象类 |
| override | `void start() override` | 签名写错又没加 override → 变成「新函数」静默不生效 |
| 虚函数选择 | 相同→普通；同格式→虚函数默认；不同→纯虚 | 该加 virtual 的没加 → 多态失效，调成基类版本 |
| 基类指针 | `Motor* p = new DaMiaoMotor();` | 反向赋值（派生类指针指向基类对象）非法 |
| 虚析构 | `virtual ~Motor()` | 忘加 virtual → `delete` 基类指针不调派生类析构 → 资源泄漏 |
| new/delete | `new T` / `delete p` | 忘 delete → 泄漏；指针数组误用 `delete[]` |

> [!tip] 核心串联
> `main` 只认识 `Motor*` 这一种类型 → `motors[i]->start()` 经**虚函数表**在运行时找到对象真实类型的实现（达妙版 / 大疆版）→ `setSpeed`（非虚，全体一致）与 `displayInfo`（虚，基类默认实现 + 各自 brand 数据）复用基类代码 → `delete` 时**虚析构**保证先 `~DaMiaoMotor()` 再 `~Motor()`。整套机制就是嵌入式里「统一驱动接口、多型号设备」的标准写法。

## 两道练习的联系

| 维度 | 练习一：传感器 | 练习二：电机 |
| --- | --- | --- |
| 组织方式 | `struct` 打包**不同字段**的数据 | `class` 继承抽象**共同行为** |
| 处理差异 | 无差异，遍历统一处理 | 品牌差异靠**重写虚函数**表达 |
| 核心语法 | 枚举、结构体、宏、指针传参 | 继承、纯虚/虚函数、多态、虚析构 |
| 内存模型 | 栈上数组，自动回收 | 堆上 `new` 对象，手动 `delete` |
| 思想演进 | C 风格「数据 + 函数」分离 | C++「数据 + 行为」封装、面向接口 |

> [!note] 一句话总结
> 练习一解决「怎么**记录和检测**数据」，练习二解决「怎么**统一驱动不同型号的设备**」：前者是数据封装，后者是行为抽象——合起来就是嵌入式上层软件最常见的两类问题。
