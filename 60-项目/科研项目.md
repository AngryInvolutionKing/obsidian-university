# 科研项目

## 05:00：自动化专业科研实践项目推荐

每天选择一个适合自动化专业本科二、三年级开展的公开 GitHub 项目或代码库，写明它能回答的具体问题、完成边界、前置知识、可复现实验与验收产出。项目推荐不把“仓库存在”写成“研究结论已成立”：涉及性能、创新性或许可证的判断须标记核验状态。

每条推荐直接写在本页，使项目、问题、实验设计和验收标准在打开笔记时即可阅读。每条至少包含可靠来源、一个可检验的研究问题、可比较的对照和可交付成果。

## 2026-10-05｜小车路径跟踪与前视距离研究

推荐项目：[AtsushiSakai/PythonRobotics](https://github.com/AtsushiSakai/PythonRobotics) 的 [Pure Pursuit 路径跟踪示例](https://github.com/AtsushiSakai/PythonRobotics/blob/master/PathTracking/pure_pursuit/pure_pursuit.py)。本次只建议研究一个清晰问题：在不同车速和路径弯曲程度下，前视距离的选取如何影响小车的横向跟踪误差与转向平滑性？2026-10-05 已读取仓库 README、`PathTracking` 目录和该源码；项目本身尚未在本机运行。

![PythonRobotics 的 Pure Pursuit 路径跟踪动画（仓库维护者提供的官方 GIF 库）](https://github.com/AtsushiSakai/PythonRoboticsGifs/raw/master/PathTracking/pure_pursuit/animation.gif)

上图来自该项目 README 明确指向的 `PythonRoboticsGifs` 官方配套仓库，用于展示参考路径与车辆轨迹，不作为任何性能结论的证据。

Pure Pursuit 依据前方目标点计算转向，示例还用比例控制调整速度。源码已有速度相关规则 $L_f=kv+L_{fc}$，所以不能把“速度相关前视距离”当作新贡献。可比较三种规则：固定前视距离、仓库原有的速度规则，以及自己提出的“速度与路径曲率联合”的候选规则。第三种是否更好必须由实验决定。

建议先用 4--6 周完成仿真。第一周跑通例程并理解状态更新；第二周保存轨迹与控制量，统一计算指标；第三周扫描原规则参数；第四周实现候选规则并作同条件比较；最后加入初始偏差或噪声并写短报告。需要 Python、向量与距离、三角函数和基础反馈控制；第一阶段普通电脑即可，不需要实体小车或 STM32。

实验中必须固定参考路径、初始状态、运动模型、时间步长、目标速度和转向限幅；调参路径与评价路径分开。至少在直线、缓弯、急弯和 S 弯上报告横向误差均方根、最大误差、转向变化幅度、完成率和实际速度。横向误差应定义为车辆后轴中心到参考折线的最短距离，不能误用到前视目标点的距离；未完成路径的样本应单列报告。

验收成果是可复现实验代码、参数配置、轨迹图、误差图、指标表，以及说明优势与失效条件的短报告。仓库 README 标示 MIT，但仓库 API 的许可证字段为 `NOASSERTION`；在使用或分发代码前仍需核验许可证全文。能完成复现和对照实验足以构成本科科研训练；创新性和可发表性尚无实验或文献证据，不能预先下结论。

## 2026-10-06｜TurtleBot3 仿真导航中的安全裕度—效率权衡

今天推荐 [ROBOTIS-GIT/turtlebot3](https://github.com/ROBOTIS-GIT/turtlebot3) 的 ROS 2 导航包，项目题目可以定为“窄通道中代价地图膨胀参数对移动机器人导航安全性与效率的影响”。它面向的不是“重新实现 Nav2”，而是把官方 TurtleBot3 Burger 的已有导航管线当作可控实验平台：在相同地图与任务下，改变障碍物周围的安全代价如何改变机器人是否能通过窄通道、离障碍物多近、走多远和耗时多久。这个问题和自动化中的感知—定位—规划—控制闭环直接相连，也能在没有实体车的前提下完成第一阶段。

代码入口是 [`turtlebot3_navigation2/launch/navigation2.launch.py`](https://github.com/ROBOTIS-GIT/turtlebot3/blob/main/turtlebot3_navigation2/launch/navigation2.launch.py) 与 [`turtlebot3_navigation2/param/burger.yaml`](https://github.com/ROBOTIS-GIT/turtlebot3/blob/main/turtlebot3_navigation2/param/burger.yaml)。前者把地图、仿真时钟和模型对应参数传给 Nav2；后者已经配置了 AMCL、局部与全局代价地图、Navfn 全局规划器和 DWB 局部规划器。Burger 的原始配置把局部/全局代价地图的膨胀半径设为 $0.5\,\mathrm{m}$、代价衰减系数设为 $5.0$，并固定了 DWB 的速度、加速度、采样数和评价项。这些现成值正好提供了明确的基线，而不是凭空挑一个算法名称。

实践范围应刻意缩小为只改 `inflation_radius` 与 `cost_scaling_factor` 两组参数；不更换全局规划器、不改机器人运动学、不接入学习算法。先用官方配套的 [ROBOTIS-GIT/turtlebot3_simulations](https://github.com/ROBOTIS-GIT/turtlebot3_simulations) 在 Gazebo 中生成两个测试环境：一个宽通道与一个仅略宽于机器人安全边界的窄通道。每个环境放置三组固定起点—终点；参数调优只在另一张训练地图进行，最终两张测试地图不得据结果反复回调参数。这样，研究对象始终是“安全裕度参数的取值”，而不是被地图、起终点或速度上限悄悄混入的综合差异。

可检验的问题是：在固定 TurtleBot3 Burger 模型、地图分辨率、起终点、Nav2 版本、速度与 DWB 配置时，膨胀半径和代价衰减系数的组合，能否在不显著降低到达率的前提下提高最小障碍物间距？先把官方默认的 $0.5\,\mathrm{m}$ 与 $5.0$ 作为基线，再预先写死例如半径 $0.30$、$0.50$、$0.70\,\mathrm{m}$ 及衰减系数 $3$、$5$、$8$ 的候选网格。实验前应明确“可接受安全距离”和超时阈值；若地图分辨率或机器人足迹变化，就重新声明该阈值，不能沿用旧结论。

公平比较时，每一组只允许改这两个 YAML 字段，并固定仓库提交版本、ROS 发行版、仿真世界、地图、激光与里程计噪声设定、起终点、最大线速度、规划超时和重复次数。报告到达率、碰撞或恢复次数、最小障碍物间距、路径长度、到达时间、平均与峰值角速度；将规划失败、超时、碰撞和到达目标分别计数，不能把失败样本从均值里悄悄删除。若使用随机噪声，应保存随机种子并对每种组合重复运行；若尚未注入噪声，则如实报告这是确定性仿真而不是鲁棒性结论。

四到六周的路线是：第一周选定与本机 ROS 2 发行版一致的分支，跑通原始地图与导航启动文件；第二周写最小数据记录脚本，确认每项指标的定义和失败分类；第三周完成训练地图上的参数网格；第四周冻结参数并在两张未参与调参的测试地图上比较；第五周加入固定强度的传感器或初始位姿扰动；第六周整理图表、配置文件和一页结果解释。先修知识是 Linux 基本操作、Python 或 C++ 的数据处理、ROS 2 的 topic/launch/参数文件、二维坐标与基础概率统计。普通电脑可先完成 Gazebo 仿真；实体 TurtleBot3、激光雷达和 OpenCR 只属于后续迁移验证，不是本任务的前置条件。

验收应交付一个可重放的 ROS 2 工作空间、未修改的官方参数副本和所有参数变体、固定地图与起终点清单、每次运行的 CSV 或 rosbag、指标汇总表、轨迹/代价地图截图，以及说明何种场景下安全性和效率发生冲突的短报告。仓库已有能力只是导航启动与参数模板；“某一参数更安全”是待检验假设；本次尚未在本机安装、编译或运行任何仿真，因此没有性能结果可报告，也不预先承诺创新性或发表价值。

核验状态：2026-10-06 已通过 GitHub 官方 API 读取主仓库 README、上述启动文件、Burger 参数文件、许可证与仓库元数据。`turtlebot3` 未归档，许可证字段为 Apache-2.0；README 明示 `humble`、`jazzy` 与 `main`（rolling）为活跃分支。上述两个关键文件最近一次提交分别为 2025-03-21 和 2025-03-25，主仓库元数据最近更新于 2026-10-05。配套仿真仓库也已核验为未归档、Apache-2.0；这些只说明源码与配置可获得，不构成运行成功或实验有效的证明。没有嵌入项目图片：主仓库 README 中可核验的图片是产品标志，不能展示导航效果，故不把装饰图当作实验材料。

## 2026-10-07｜simple-pid 温控实验：积分限幅与回算抗饱和

今天推荐 [m-lundberg/simple-pid](https://github.com/m-lundberg/simple-pid)，实践题目为“加热功率受限时，积分处理方式如何影响温度跟踪与恢复”。加热器达到最大功率后，继续增大控制指令已经不能增加加热能力；如果积分项仍持续累积，温度接近目标时可能继续大功率加热，或在目标温度降低后迟迟不能退出饱和。这个项目能把误差、反馈、积分、执行器约束和动态响应连接起来，适合自动化专业大二、三学生用普通电脑开展一个范围明确的控制实验。

具体代码入口是 [`simple_pid/pid.py`](https://github.com/m-lundberg/simple-pid/blob/6e6f4b000cdf7830635674cb89a6e823f5025784/simple_pid/pid.py) 中的 `PID.__call__()`，以及 [`examples/water_boiler/water_boiler.py`](https://github.com/m-lundberg/simple-pid/blob/6e6f4b000cdf7830635674cb89a6e823f5025784/examples/water_boiler/water_boiler.py) 中的 `WaterBoiler.update()` 和闭环循环。前者计算比例、积分、微分项，并对积分项和最终输出分别限幅；后者演示温度测量如何送入控制器，再由功率驱动被控对象。可以用 `PID(Kp, Ki, 0, sample_time=None, output_limits=(0, 1))` 构造 PI 基线，每步调用 `pid(T_meas, dt=0.1)`，并用 `pid.components` 记录各项贡献。这些接口已与[作者 API 文档](https://simple-pid.readthedocs.io/en/latest/reference.html)核对；代码中的增益和测量量仍须由实验程序定义。

仓库自带的水锅炉示例采用简化的功率加热和固定散热项，并按真实时钟运行约十秒。它适合读懂闭环结构。为了得到可重复的对照，本项目在自己的实验目录中保留上游源码副本，另写固定仿真步长的对象与记录程序，第一阶段统一令微分增益为零，只研究积分处理方式。仓库已经具备积分数值限幅；把它作为正式基线，回算抗饱和作为需要自行实现并检验的另一种已有方法。

建议使用如下自建的一阶温度对象。令 $T$ 为真实温度，$T_a$ 为环境温度，$u\in[0,1]$ 为归一化加热功率，$d$ 为与温度同量纲的等效热负荷项，$y$ 为送给控制器的测量值：

$$
\tau\frac{dT}{dt}=-(T-T_a)+Ku+d,
\qquad y=T+\varepsilon.
$$

用固定步长的前向欧拉法更新：

$$
T_{k+1}=T_k+\frac{\Delta t}{\tau}
\left[-(T_k-T_a)+Ku_k+d_k\right].
$$

拟定 $T_a=20\,^{\circ}\mathrm C$、$T_0=20\,^{\circ}\mathrm C$、$\Delta t=0.1\,\mathrm s$，每次运行六百秒。名义对象为 $\tau=60\,\mathrm s$、$K=80\,^{\circ}\mathrm C$，评价对象取 $\tau\in\{30,60,90\}\,\mathrm s$ 与 $K\in\{60,80,100\}\,^{\circ}\mathrm C$ 的组合。这里 $K$ 表示满功率时相对于环境温度的稳态温升；这些数值是拟定的仿真参数，未由真实设备辨识，也不是仓库提供的水锅炉参数。

比较三类控制器：第一类仅将最终功率截断到 $[0,1]$，积分项不设限，用来观察积分累积的作用；第二类保留 simple-pid 的积分限幅与输出限幅；第三类用回算修正积分项，同时保持相同的最终功率限制。若实现第一类，应在独立实验副本中只移除积分项的限幅，保留最终输出限幅；直接取消 `output_limits` 会同时改变执行器约束，使比较失去解释力。

回算版本可以明确规定如下离散计算顺序。先令 $e_k=r_k-y_k$，其中 $r_k$ 为目标温度，再计算

$$
\begin{aligned}
\widetilde I_k&=I_{k-1}+K_i e_k\Delta t,\\
v_k&=K_p e_k+\widetilde I_k,\\
u_k&=\operatorname{clip}(v_k,0,1),\\
I_k&=\widetilde I_k+\frac{\Delta t}{T_t}(u_k-v_k).
\end{aligned}
$$

其中 $v_k$ 是限幅前的功率指令，$T_t>0$ 是回算时间常数，修正后的 $I_k$ 进入下一步。功率受到上限约束时，$u_k-v_k$ 为负，反馈项会抵消一部分积分累积。该版本不再同时套用库内的积分数值限幅，否则会混入两种机制。回算使用饱和前后控制量的差来修正积分器，是已有抗饱和思路，原理可参见 [MathWorks 官方说明](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)。上式是本项目选定的离散实现方案，尚未执行验证。

可检验的研究问题是：在相同 PI 增益、采样周期和功率限制下，回算抗饱和相对于仓库积分限幅，能否缩短目标温度下降或冷负荷加入后的恢复时间，并降低积分绝对误差？待检验的假设是回算能够减轻饱和后的积分残留，但不同 $T_t$ 可能改变升温速度与恢复效果；结果也可能表明库内积分限幅已足够。结论应明确对应的参数和工况。

公平对照需固定比例项按误差计算、$K_d=0$、初始积分为零，并让各方法共享同一组 $K_p,K_i$。可从 $K_p=0.05\,({}^{\circ}\mathrm C)^{-1}$、$K_i=0.001\,({}^{\circ}\mathrm C\cdot\mathrm s)^{-1}$ 开始，在名义对象上检查响应后确定共同增益，再冻结它们。其余八组对象不参与增益选择。回算时间常数预先取 $T_t\in\{30,60,120\}\,\mathrm s$，三个候选都报告；不根据测试结果挑选一个最好值来代表全部回算控制器。整个实验只改变积分处理方式，共享模型更新顺序、步长、初始状态、运行长度、目标序列和扰动。

测试采用两个单独工况。目标反转工况在开始时把目标设为 $60\,^{\circ}\mathrm C$，三百秒时降到 $30\,^{\circ}\mathrm C$，全程 $d=0$；负荷工况将目标保持在 $60\,^{\circ}\mathrm C$，三百秒时令 $d$ 从零变为 $-10\,^{\circ}\mathrm C$ 并保持。先由 $T_\infty=T_a+Ku+d$ 检查目标是否可达：本组参数下，两个目标均在对应功率范围内。运行前还应确认升温段确实触及功率上限，否则该工况难以揭示抗饱和差异。先完成无噪声比较，再加入标准差 $0.5\,^{\circ}\mathrm C$ 的零均值高斯测量噪声，使用二十个固定种子；同一对象、工况和种子的不同控制器使用同一条噪声序列。

指标用真实温度计算，带噪测量值只用于控制。积分绝对误差定义为

$$
\mathrm{IAE}=\Delta t\sum_k|r_k-T_k|.
$$

分别报告变化前、变化后的 IAE，上升段超调、下降段欠调，以及目标或负荷变化后首次进入 $\pm1\,^{\circ}\mathrm C$ 误差带并连续保持六十秒所需的时间。六百秒内没有满足条件的运行记为“未恢复”，同时报告发生比例。还要画出积分项、限幅前指令与实际功率，统计处于功率上下限的时间比例，才能判断差异是否来自饱和处理。$\Delta t\sum_k u_k$ 只称为归一化加热投入；没有额定功率就不能写成实际能耗。每个对象和工况单独汇总，同一种子进行配对比较，采样时刻不能当作独立实验样本。

先修知识包括 Python 函数与类、循环和数据保存，比例积分反馈的含义，一阶微分方程及欧拉离散，以及均值、标准差和随机种子的作用。软件方面需要 Python、simple-pid，以及示例声明的 NumPy、Matplotlib；[项目配置](https://github.com/m-lundberg/simple-pid/blob/6e6f4b000cdf7830635674cb89a6e823f5025784/pyproject.toml)声明 Python 版本至少为 3.6，复现时还应记录实际使用的解释器与依赖版本。第一阶段普通 Windows 或 Linux 电脑即可，不要求购买加热器、开发板或传感器。

六周路线可以这样安排：第一周读 `PID.__call__()` 并运行官方水锅炉示例，解释每个状态量；第二周建立固定步长的一阶对象，保存时间、目标、真实温度、测量温度、功率和积分项；第三周实现两种实验副本，与库内限幅基线核对非饱和阶段的计算，并确认饱和修正方向；第四周冻结共同增益，在八组未参与调参的对象和两个工况上完成比较；第五周加入配对噪声试验，检查恢复率和误差差值；第六周整理图表、配置与短报告。时间只有四周时，可以先交付无噪声对照，把噪声部分作为后续扩展。

## 2026-10-11｜CVXPY：受容量约束的多执行器分配

推荐 [cvxpy/cvxpy](https://github.com/cvxpy/cvxpy)。它提供凸优化问题的 Python 建模、规范化与求解器接口。把实践缩小为三个执行器共同承担总需求的静态分配问题，可以把线性代数、二次型与自动化系统中的控制分配、饱和约束联系起来。这里的执行器是仿真抽象，可理解为并联泵或协同出力单元，不假定真实设备的效率曲线。

固定提交 `0049909353bb649fcb89f427a3dd2eb9702d6d00` 的入口是 [README](https://github.com/cvxpy/cvxpy/blob/0049909353bb649fcb89f427a3dd2eb9702d6d00/README.md)、[二次规划示例](https://github.com/cvxpy/cvxpy/blob/0049909353bb649fcb89f427a3dd2eb9702d6d00/doc/source/examples/basic/quadratic_program.rst) 和 [Problem.solve 实现](https://github.com/cvxpy/cvxpy/blob/0049909353bb649fcb89f427a3dd2eb9702d6d00/cvxpy/problems/problem.py)。先从 `Variable`、`Minimize`、约束列表到 `Problem.solve()` 走通一次，再读 `status`、`value` 与 `solver_stats`；建模层将问题交给数值求解器完成求解。本次分配模型是学生新增实例。

先修知识为 Python、矩阵和向量、二次型、拉格朗日乘子与基本凸性。普通电脑即可。当前核验提交的 README 要求 Python 至少 3.11，并列有 NumPy、SciPy 及求解器依赖；安装时记录实际版本和 `installed_solvers()` 返回值。第一阶段选择 OSQP 求解这一凸二次问题，不需要硬件或商业求解器。

可检验问题是：给定相同总需求和相同容量，按二次成本优化的分配，相比等份后容量重分配的策略能降低多少归一化成本，优势怎样随成本不均匀程度与饱和位置变化？基础模型为

$$
\min_{u\in\mathbb{R}^3}\sum_{i=1}^3\alpha_i u_i^2,\qquad \sum_{i=1}^3u_i=d,\quad0\leq u_i\leq c_i.
$$

拟取容量 $c=(0.6,0.8,1.0)$，成本权重分别为 $(1,1,1)$、$(1,2,4)$、$(4,2,1)$，需求从零到总容量之间取 49 个等距点。所有成本均为归一化代理量；没有实测功率曲线时，不能把它们写成节省了多少电能。

公平基线从等份 $d/3$ 开始：达到容量的执行器固定在上限，剩余需求继续在其余执行器间等分，重复直到分配完成。这保证基线也满足需求和容量，避免拿“分别裁剪后需求不足”的错误基线制造优势。每个成本组和需求点同时计算基线及优化解，不在测试点上改权重或约束。

本模型还有独立参考解：由最优性条件得到 $u_i=\min\{c_i,\lambda/(2\alpha_i)\}$，选择 $\lambda\geq0$ 使总和等于 $d$，可用二分法或枚举饱和集合实现。比较 CVXPY 解与这份独立实现，检查成本、需求残差及容量违反，而非只相信求解状态。故“优化不会比任何可行基线更差”是精确模型最优解的数学性质；数值实验要核实误差大小，并量化这种特定基线的差距。

指标为需求残差、最大约束违反、归一化成本、与独立参考解的差值、求解失败数量和端到端耗时。成本差使用绝对差；相对改善在基线成本为零时留空。测试需求超过总容量的一组额外案例时，应如实报告不可行，不能把需求悄悄裁剪后冒充原题的解。

效率扩展单独比较每次重建问题与使用 `Parameter` 复用问题；按 [官方性能文档](https://www.cvxpy.org/tutorial/performance/index.html) 检查 `is_dpp()`，共享求解器、精度与输入顺序。首次构建和首次求解单列，后续请求耗时另列；暖启动设置一致，端到端计时包括建模与规范化。基础成本实验和效率实验回答不同问题，各自保持自己的公平条件。

五周路线为：第一周复现官方二次规划并理解状态；第二周建立三执行器模型及可行基线；第三周写解析最优性条件对应的独立参考解、检查边界和不可行案例；第四周完成三成本组与需求网格并整理成本差；第五周加入参数复用计时，完成复现说明。六周可加入变化率约束，但应重新建立可行基线和参考核验。

## 2026-10-12｜Bullet/PyBullet：单关节显式 PD 与 Stable PD 的采样周期对照

推荐 [bulletphysics/bullet3](https://github.com/bulletphysics/bullet3)。这是 Bullet Physics SDK 的官方仓库，提供刚体动力学、碰撞检测及 PyBullet Python 接口，实际用于机器人等系统的物理仿真。已有学习笔记讨论了编码器角速度与电机 PWM，本项目进一步把角度、速度和力矩连接成反馈回路。适合自动化专业本科二、三年级先完成一个电脑上的关节控制实验，再考虑硬件；不要求购买机械臂或学习强化学习。

本次固定默认分支提交 `d3afe76132fc76b0f9b2359cbaef47a3766e7fbb`。代码入口是 [pdControl.py](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/examples/pybullet/examples/pdControl.py)，其中演示关闭默认关节电机、设置仿真步长、计算控制力及执行 `stepSimulation()`；显式控制器入口是 [pdControllerExplicit.py](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/examples/pybullet/examples/pdControllerExplicit.py) 中的 `PDControllerExplicit.computePD()`；对照入口是 [pdControllerStable.py](https://github.com/bulletphysics/bullet3/blob/d3afe76132fc76b0f9b2359cbaef47a3766e7fbb/examples/pybullet/examples/pdControllerStable.py) 中的 `PDControllerStable.computePD()`。后者读取质量矩阵和逆动力学项，求解线性方程后限幅。原示例使用四个 cart-pole 模型比较多种控制方式，本次缩小为一个关节、两种控制器；这个单关节实验属于待新增内容。

先修知识是 Python 函数和数组、角度与角速度、转动惯量、二阶微分方程、PD 反馈及零阶保持。软件需要可安装 PyBullet 的 Python 环境、NumPy 和用于画图的 Matplotlib，记录实际 Python、PyBullet、NumPy 版本。普通电脑即可，基础计算无需 GPU；先确认所用解释器有可用安装包并跑通最小示例，尚未核验本机安装兼容性。可以用无界面的批量仿真保存数据，最后再用可视化检查运动。

可检验研究问题是：**在相同连续 PD 增益、相同力矩上限与相同物理积分精度下，增大控制采样周期时，Stable PD 相比显式 PD 能否扩大满足误差与恢复时间要求的周期范围，饱和是否改变这种差异？** 名称中的 Stable 不构成对任意步长、增益或饱和条件的稳定性保证，效果必须逐工况检验。

缩小范围为固定基座、一个刚体和一个连续旋转关节，总关节数为 1，索引列表为 `[0]`，避免混入固定关节或多自由度接口。关闭重力、不加接触，模型关节阻尼设为零；先以零输入匀速试验检查是否仍有隐含阻尼，再核对运行时质量矩阵中的标量惯量 $I$。这类结构可近似成 $I\ddot q=\tau$。模型文件、惯量检查和零输入试验都尚未执行，不能把它当作真实电机的完整模型。

零目标速度、角度误差 $e=q_d-q$ 时，显式 PD 的未限幅力矩是 $\tau_E=k_pe-k_d\dot q$。将已读取的 Stable PD 源码化简到单关节、无重力的情形，未限幅力矩为

$$
\tau_S=\frac{k_pe-(k_d+k_ph)\dot q}{1+k_dh/I},
$$

其中 $h$ 是传给控制器的采样周期。两者最后都采用同一个 $[-\tau_{\max},\tau_{\max}]$ 限幅。该式已按源码中的中间加速度方程进行代数核对；这只是公式核验，尚不是仿真性能结果。对复杂机构，应继续用源码的质量矩阵与逆动力学计算，不能直接套这个标量式。

拟定基础实验初态为 $q=0,\dot q=0$，目标阶跃为 $q_d=0.3$ rad，运行 6 秒。选择自然频率 $\omega_n\in\{10,20,40\}$ rad/s、阻尼比 $\zeta=1$，共同设置 $k_p=I\omega_n^2$、$k_d=2\zeta I\omega_n$，并比较 $\tau_{\max}/I\in\{50,200\}$ rad/s²。每个工况的两控制器使用完全相同的增益和上限，不为其中一方单独调参。

公平对照取控制周期 $h\in\{0.001,0.002,0.005,0.01,0.02,0.05\}$ 秒，共 36 个条件、每条件一对控制器。物理积分步长固定为 0.0005 秒，控制器只在对应采样时刻计算力矩，期间保持输出；按原示例的方法关闭默认关节电机，避免内置控制器暗中参与。原官方演示一起调整物理步长，本实践把物理步长与控制周期分开。Stable PD 的 `timeStep` 传入控制周期是本实验采用的应用选择，须在第一阶段确认两接口和保持策略一致。

另建独立的理想转子参考：在每个力矩保持区间用 $q_{k+1}=q_k+h\dot q_k+h^2\tau_k/(2I)$、$\dot q_{k+1}=\dot q_k+h\tau_k/I$ 精确推进，与 PyBullet 结果比较。这可以检查是否由仿真积分或模型设置引入差异；它没有覆盖真实摩擦、接触、传感器噪声和执行延迟。若加入这些因素，应另设扩展实验，保留原来的基础对照。

指标包括角度 IAE、最大绝对误差、超调量、进入并在余下时间持续满足 $|e|\leq0.01$ rad 和 $|\dot q|\leq0.05$ rad/s 的恢复时间、力矩 RMS、限幅时间比例，以及实际控制调用次数。未在 6 秒内恢复的条件报告未恢复；非有限值或 $|q|>3$ rad 时终止并计为失效。逐条件保存两方案的配对指标，不丢弃失效样本。基础实验是确定性的，不把重复同一轨迹作为独立统计样本，也不把力矩平方指标写成实际电耗。

五周路线可以这样推进：第一周读三个入口，解释关闭默认电机、状态读取、质量矩阵及力矩控制；第二周建立单关节模型，核对惯量和零输入运动，保存角度、速度及实际输出；第三周实现固定物理步长与不同控制周期，加入独立解析参考；第四周冻结共同设置，完成 36 个成对工况；第五周绘制误差、限幅和恢复时间图，回答差异出现在哪些条件及其可能机制。四周可先缩减频率网格，六周可加一组统一的测量噪声扩展。
