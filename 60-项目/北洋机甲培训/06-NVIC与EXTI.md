6.NVIC与EXTI
一、中断
1.1 中断的概念
在我们前面的学习中，已经了解到了GPIO相关用法。那么，假如我们要完成用一个按键去控制LED亮
灭的程序，很容易想到这样的写法：
while(1){
if(HAL_GPIO_ReadPin(KEY_PORT, KEY_PIN) == GPIO_PIN_RESET){
HAL_GPIO_TogglePin(LED_PORT, LED_PIN);
}
}
这么做虽然可以控制小灯亮灭，但如果想要让程序在小灯亮灭的同时完成其他效果，比如说控制呼吸
灯效果，就会造成CPU被不停的"读取按键"这件事情所绑死，而无法执行。
那我们就会开始想，能不能让CPU该干嘛干嘛，只有当按键按下去的时候再进行处理？
这个想法的最终体现就是 中断。通俗来讲，中断就是打断CPU执行正常的程序，转而处理紧急程序，
处理完后返回原来正常程序暂停的位置，并继续运行。
1.2 前置知识：函数指针与回调函数
在正式讲NVIC和EXTI之前，我们需要先补充一个C语言的知识点——回调函数。
要理解回调函数，得先从函数指针说起。
函数指针：指向函数的指针
我们已经学过指针——指针是一个变量，存的是某个数据的地址。比如int *p 存的是一个int 变
量的地址。
那函数有没有地址？当然有。程序运行时，函数的代码也是存在内存里的，函数名本身就是这个函数
的入口地址。既然有地址，就能用指针存起来——存函数地址的指针，就叫函数指针。
来看一个最简单的例子：
#include <stdio.h>

// 定义一个普通函数
void say_hello(int num)
{
printf("Hello! 你传入的数字是：%d\n", num);
}

int main()
{
// 定义一个函数指针 p
// 返回值是 void，参数是一个 int
void (*p)(int);

// 让 p 指向 say_hello 函数（函数名就是地址，不用加 &）
p = say_hello;

// 通过函数指针调用函数，两种写法都可以
p(100);           // 写法一：直接当函数名用
(*p)(200);        // 写法二：先解引用再调用

return 0;
}
运行结果：
Hello! 你传入的数字是：100
Hello! 你传入的数字是：200
函数指针的定义语法稍微有点绕，记住这个格式就行：
返回值类型 (*指针名)(参数类型列表);
比如void (*p)(int) 的意思是：定义一个指针p ，它指向的函数返回值是void ，接受一个
int 参数。
回调函数：被别人调用的函数
有了函数指针，回调函数就很好理解了。
回调函数就是一个通过函数指针调用的函数。 你把一个函数的地址（函数名）作为参数传给另一个函
数，当这个函数在合适的时候用函数指针调用你传进去的那个函数，被调用的那个函数就是回调函
数。
听起来有点绕，用一个生活中的例子就清楚了。
假设你点外卖：
•
平台会把你的电话号码告诉小哥。这里的"电话号码"就相当于函数指针——它指向了"通知你"这
个动作。
•
小哥把外卖送到宿舍楼下（这是朋友自己的主任务）。
•
完成后，小哥拨打电话通知你（小哥通过你留下的"函数指针"，调用了你提供的"回调函数"）。
整个过程中，你不需要在楼下干等，送到后小哥会自动通知你。这就是回调的核心思想：把"做什
么"和"什么时候做"分开——你负责写"做什么"，别人负责在合适的时候调用它。
来看一个代码例子，体会一下回调的用法：
#include <stdio.h>

// 回调函数1：打印元素
void print_element(int num)
{
printf("%d ", num);
}

// 回调函数2：打印元素的平方
void print_square(int num)
{
printf("%d ", num * num);
}

// action 就是一个函数指针，接受一个 int 参数，返回 void

{
for (int i = 0; i < len; i++)
{
action(arr[i]);  // 调用回调函数
}
printf("\n");
}

int main()
{
int arr[] = {1, 2, 3, 4, 5};
int len = 5;

printf("原数组：");
for_each(arr, len, print_element);   // 传入 print_element 作为回调

printf("平方后：");
for_each(arr, len, print_square);    // 传入 print_square 作为回调

}
运行结果：

平方后：1 4 9 16 25
看到了吗？for_each函数的遍历逻辑是固定的，但每个元素具体做什么，由传入的回调函数决定。同
一个for_each，传print_element就打印原值，传print_square就打印平方。这就是回调的威力：把流
程和具体动作解耦，同一个流程可以搭配不同的动作。
弱函数：可以被覆盖的默认实现
在嵌入式开发中，回调函数经常和一个叫做弱函数的东西搭配使用。
弱函数用__attribute__((weak))修饰，特点是：它提供了一个默认实现，但如果用户自己写了一个同
名的函数（不加weak），用户写的那个就会覆盖默认实现。
来看一个例子：
#include <stdio.h>

{

}

int main()
{

}
如果用户什么都不写，运行结果是：

【默认】按键按下了，但用户没有写处理逻辑
但如果用户在另一个文件里写了一个同名函数（不加weak）：
// 用户自己写的，覆盖弱函数

{
printf("【用户】按键按下了，我要点亮LED！\n");
}
运行结果就变成了：
模拟按键按下...
【用户】按键按下了，我要点亮LED！
一句话总结弱函数： 库的作者给你留了一个"默认是空的"函数，你需要的时候就自己写一个同名的
把它覆盖掉，不需要就不管它，程序也能正常跑。这是HAL库最核心的设计思想之一。

二、NVIC——中断管家
2.1 前言
在我们目前所使用的STM32系列芯片当中，设置了专门用来处理中断的控制器——NVIC，即嵌套向量
中断控制器（Nested Vectored Interrupt Controller）。NVIC通过中断优先级管理、嵌套中断处理以
及中断向量的跳转来管理和协调处理器的中断请求，是STM32中处理异步事件的重要机制。
说白了，NVIC就是专门帮CPU管中断的管家。
2.2 NVIC的硬件原理
既然叫"中断管家"，那这个管家具体干些什么呢？我们来拆解一下。
NVIC是Cortex-M内核的一部分，属于内核外设——它和CPU是一体的，不是外挂在总线上的片上外
设。所有中断（包括GPIO外部中断、定时器中断、串口中断等等）都要先经过NVIC，才能到达CPU。
这里区分一下内核外设和片上外设：它们都在芯片里面，但内核外设是在CPU内核里面（比如
NVIC、SysTick），片上外设是在内核之外、通过总线和CPU相连（比如GPIO、EXTI、USART、
TIM）。NVIC是我们遇到的第一个内核外设。
管家的工作可以分成三步：
第一步：门卫——中断使能
每个中断都有一个独立的开关。开关打开，这个中断的请求才能被NVIC接收；开关关着，不管外部怎
么喊，NVIC都直接忽略，CPU根本不知道有这件事。
就像管家先确认"今天见不见客"，不见的话，门口喊破喉咙也没用。
这个开关在硬件上由中断使能寄存器（ISER） 和 中断失能寄存器（ICER控制，后面讲寄存器时会细
说。这里你只需要知道：NVIC的第一道关卡是使能，没使能的中断进不来。
第二步：调度员——优先级裁决
假设多个中断同时使能了，而且同时来了请求——比如按键按下的同时，串口也收到了数据——CPU
先处理谁？
这就是NVIC的核心工作：比较所有待处理中断的优先级，选出最高的那个，把它送到CPU。
优先级分两级：
•
抢占优先级：决定能不能插队
•
响应优先级：抢占优先级一样时，决定谁先排队
就像管家同时收到好几个客人的拜访请求，按客人的重要程度排个顺序，最重要的先见。
第三步：管家的核心能力——中断嵌套
这是NVIC最厉害的地方，也是它名字里"Nested（嵌套）"的由来。
NVIC会时刻盯着：现在CPU正在处理哪个中断？它的抢占优先级是多少？
如果此时来了一个新中断，NVIC会比较：
•
新中断的抢占优先级 更高 → 让CPU暂停当前中断，先处理这个新的，处理完再回来继续。这就是
中断嵌套。
•
新中断的抢占优先级 更低或相等 → 排队等着，等当前中断处理完再说。
就像你正在跟一个普通客人谈话，突然老板来了电话——你得暂停谈话先接老板的电话，接完再回来
继续聊。老板的电话就是高抢占优先级的中断。
注意：嵌套是NVIC硬件自动完成的，不需要你在代码里写判断逻辑。 你只需要配置好优先级，剩下的
NVIC自己搞定。
中断向量表——管家和CPU之间的通讯录
NVIC裁决完之后，并不直接告诉CPU"去执行哪个函数"，它只告诉CPU一个编号："该处理第x号中断
了。"
CPU拿到编号后，去一张叫做中断向量表的表里查地址——这张表里存着每一个中断对应的服务函数
的入口地址，就像一个通讯录：编号对应函数地址。CPU查到地址后，跳过去执行，执行完再回到原
来被打断的地方继续。
管家只说"见3号客人"，CPU自己翻通讯录找到3号客人在哪个房间，然后过去。
NVIC完整工作流程
把上面三步串起来，NVIC处理一个中断的完整流程是：
当外部被触发时，首先进入到ISER、ICER寄存器，来判断是否开启对应的中断，中断开启后，进入到
IPR寄存器，进行中断优先级判断，其中IPR寄存器受到AIRCR寄存器控制，最后NVIC会确定其优先级
并根据优先级决定传入CPU的次序。
接下来，进入CPU的事件根据优先级抢占CPU使用权，然后CPU会查询中断向量表,以查找到相应的中
断服务程序地址。最后,CPU会将控制转移到该地址,以执行相应的中断服务。

2.4 中断优先级
在单片机执行主程序时，突然遇到了两个及两个以上的突发事件，单片机将先运行哪一部分程序呢？
这便需要用中断优先级来处理。
中断优先级即给不同的中断划分不同的响应等级，如果多个中断同时发生，则STM32优先处理高优先
级的中断。
中断优先级主要被分为两类：抢占优先级与响应优先级。
- 抢占优先级是抢占式的（数值越小优先级越高，0 > 1 > 2 > 3……），即优先级高的中断到来时，即使
优先级较低的中断正在执行，也要停下来先执行优先级较高的中断。
- 响应优先级是非抢占式的，即当响应优先级比较低的中断在执行，如果抢占优先级相同，响应优先级
较高的中断到来，那么要等这个响应优先级比较低的中断执行完，再执行后到来的中断。
当抢占优先级相同、响应优先级不同的两个中断同时需要被执行的时候，先执行响应优先级较高的中
断。

级。

2.6 中断嵌套
通过对抢占优先级与响应优先级的比较，我们了解到当高抢占优先级中断发生时，系统会暂停当前执
行的中断（无论其优先级高低），转而处理高优先级中断。这种特性我们将其称为中断嵌套。中断嵌
套是NVIC的核心功能之一。
2.7 中断向量表
中断向量表是单片机处理中断机制的核心数据结构，其作用类似于硬件与中断服务程序之间的"导航地
图"。它直接决定了系统在中断触发时如何快速定位到对应的处理代码。
中断向量表存放着中断服务函数的首地址，由四字节对齐，由地址找到我们对应的中断服务函数。中
断向量表定义在startup启动文件中，当发生中断时，CPU会根据中断向量表找到要执行的中断服务函
数的首地址，自动执行对应的中断服务函数。

三、EXTI——外部中断
3.1 初识外部中断
外部中断是指微控制器（如STM32）中一种由外部硬件信号触发的中断机制，用于快速响应引脚（通
常是我们刚刚学过的GPIO引脚）电平变化（如按键按下、传感器信号）触发的中断。
注意：外部中断的"外部"可不是单片机外部哦，而是内核外部，也就是上文所说的片上。在后续的学
习中我们还会接触很多不同种的中断，本次我们先来学习GPIO电平跳变而引起的外部中断。（有能力
的同学可以多了解一些其他中断，如定时中断。）
3.2 EXTI是什么？
EXTI（外部中断/事件控制器）作为STM32的一个外设，是STM32中用于处理外部中断和事件的模块。
EXTI可分为两大部分功能：
- 产生中断：当检测到指定GPIO引脚上的电平变化时，产生一个中断请求，最终信号流入NVIC控制器
内。
- 产生事件：当检测到指定GPIO引脚上的电平变化时，产生一个事件信号，可用于软件轮询或其他外
设（如DMA）。
这两个功能从硬件上就有所不同。第二个功能同学们可以自行了解，后续会讲。
3.3 外部中断触发完整流程
首先我们来看EXTI功能框图中红色虚线指示的电路流程，它是一个产生中断的线路，最终信号流入到
NVIC控制器内。
编号1：输入线
EXTI控制器有19个中断/事件输入线，这些输入线可以通过寄存器设置为任意一个GPIO，也可以是一
些外设的事件。
在STM32中，每一个GPIO都可以作为外部中断的触发源，外部中断一共有16根线，但STM32的GPIO
口多达上百个，同时每个GPIO都有很多引脚，如果每个GPIO的引脚都占用一个EXTI中的GPIO通道，
那么EXTI中的GPIO通道明显不够用，那么怎么办？
单片机通过AFIO实现中断引脚选择。什么是AFIO？AFIO实际上就是一个数据选择器，它可以选择所有
GPIO的其中的16个引脚接入到EXTI的通道中。这样，众多GPIO口就被成功分组，一条外部中断线对应
相应的一组GPIO口。112个通用I/O端口以下图的方式连接到16个外部中断/事件线上。
如图：
每一条外部中断都可以与任意一组的对应引脚相连，但不能重复使用。比如，外部中断Line0可以和
PA0、PB0、PC0等任意一条0号引脚相连，但如果已经和PA0相连接，则不能同时与PB0、PC0等0号
引脚相连。
对数字比较敏感的同学可能会疑问，为什么介绍编号1的时候说EXTI有19条中断/事件输入线，而112个
GPIO口最终只连接到了16条中断线上呢？那是因为不仅是GPIO可以作为外部中断的输入，还有其他
的：
•
EXTI_Line16为PVD输出（EXTI的电源电压检测中断）
•
EXTI_Line17为RTC Alarm（RTC闹钟唤醒中断）
•
EXTI_Line18为USB唤醒事件
这三条中断线我们不会用到，只做了解即可。
外部中断的触发方式
外部中断的触发主要通过GPIO口的电平变化来触发。外部中断支持GPIO三种电平跳变模式：
1. 上升沿中断：当GPIO的电平从低电平跳变成高电平时，引发外部中断。
2. 下降沿中断：当GPIO的电平从高电平跳变成低电平时，引发外部中断。
3. 上升沿和下降沿中断：当GPIO的电平从低电平跳变成高电平时，或者从高电平跳变成低电平时，都
可以引发外部中断。
编号2：边沿检测电路
边沿检测电路会根据上升沿触发选择寄存器（EXTI_RTSR）和下降沿触发选择寄存器（EXTI_FTSR）
对应位的设置来控制信号触发。边沿检测电路以输入线作为信号输入端，如果检测到有边沿跳变就输
出有效信号1给编号3电路，否则输出无效信号0。
而EXTI_RTSR和EXTI_FTSR两个寄存器可以控制需要检测哪些类型的电平跳变过程，可以是只有上升
沿触发、只有下降沿触发，或者上升沿和下降沿都触发。
流程总结
总体来说，当GPIO口发生电平跳变时，通过AFIO选择对应的中断引脚，通向EXTI边沿检测，最后通过
中断通道至NVIC中断控制器发出中断。

EXTI_IRQHandler——中断服务函数
当我们打开EXTI Line3 interrupt时，并且在CubeMX的Code generation中配置了generate IRQ

它就是我们触发外部中断（比如按下按键触发中断后）STM32会调用执行的中断处理函数。中断向量

首地址来到该函数并开始运行。

2. 调用HAL_GPIO_EXTI_Callback 回调函数
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin);
•
功能：外部中断回调函数，弱函数，用户重写后在中断触发时自动调用
•
参数：GPIO_Pin ——触发中断的引脚号，如GPIO_PIN_1
•
返回值：无
HAL库中实现：./Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_gpio.c
HAL_GPIO_EXTI_Callback 是一个弱函数，当外部中断被触发时，系统会自动调用该函数，并将
触发中断的GPIO的引脚号作为参数传入。如果想要应用此函数，只需要不加weak在主程序中写一个同

3.7 注意：中断里不能用HAL_Delay
HAL_Delay() 是一个延时函数，输入我们想要延长的时间，单位默认是毫秒，程序运行到这里的时
候便会在这里停留你设置的那段时间，之后再继续运行下面的程序。
但是——千万不要在中断里用延时函数！
当我们在中断中使用HAL_Delay() 函数时，当中断触发条件发生时，跳入到存在HAL_Delay()
函数的延时中断中，会出现死机的情况。这是因为中断优先级的缘故：中断优先级高的能抢占CPU的
资源，延时函数中含有一个优先级较低的中断用来记录时间，由于中断优先级比较低，而当前正在处
于优先级比较高的中断，所以无法进入到用来计时的中断，那么延时函数中的计时就会停止。
HAL_Delay() 是通过轮询系统时间阻塞住CPU直到到了时间才会跳出循环的延时函数，而计时中止
了，HAL_Delay() 也无法到达设定值，所以程序将一直卡在这。
这里是比较笼统的说法，如果了解定时器等知识的同学可以点开链接更详细地看一看具体原因：

3.8 按键消抖
如果按键感觉不灵敏，小同学们可以了解一下按键消抖。
当机械触点断开、闭合时，即按下按钮和松开按钮时，由于机械触点的弹性作用，一个按键开关在闭
合时不会马上稳定地接通，在断开时也不会一下子断开。因而在闭合及断开的瞬间均伴随有一连串的
抖动。为了不产生这种现象而作的措施就是按键消抖。
单片机如果在触点抖动期间检测按键的通断状态，则可能导致判断出错，即按键一次按下或释放被错
误地认为是多次操作，从而引起误处理。因此，为了确保单片机对一次按键动作只作一次响应，就必
须考虑如何消除按键抖动的影响。
按键消抖有很多方式，我们主要是要软件消抖，从我们的代码层面来消抖。最常用的方法是：检测出
键闭合后执行一个延时程序，5ms~10ms的延时，让前沿抖动消失后再一次检测键的状态，如果仍保
持闭合状态电平，则确认为真正有键按下。当检测到按键释放后，也要给5ms~10ms的延时，待后沿
抖动消失后才能转入该键的处理程序。
同学们可以根据这段描述编写出代码用于按键消抖。
